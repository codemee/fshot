# macOS 虛擬螢幕分階段實作

分支：`macOS_v_screen`。

## 第一階段：既有螢幕上的作用中視窗擷取

已實作：使用者選擇既有 4K 延伸螢幕、UUID 持久化、AX 視窗身分／幾何保存、points 比例換算、ScreenCaptureKit 原生 pixels 擷取、倒數取消及錯誤還原、獨立 repeat 紀錄。

不支援：螢幕建立、控制項虛擬擷取、互動預覽。拒絕最小化／全螢幕／不可縮放視窗。

程式測試涵蓋 HiDPI 尺寸、負座標、目的螢幕配置變更、部分搬移失敗、擷取錯誤、取消與還原。原生框架方法及 UUID 橋接已確認；已使用 BetterDisplay 建立 `FShot-4K`，第一階段經使用者手動驗收通過。

驗收步驟：

1. 以 BetterDisplay 或 DeskPad 建立並啟用 3840 × 2160 延伸螢幕，授予 FShot 輔助使用及螢幕錄製權限。
2. `uv run fshot`，切換虛擬模式並選擇目的螢幕。
3. 用可調整尺寸的普通視窗按 `Ctrl+Shift+A`，確認輸出像素尺寸、原位置與大小還原。
4. 設定延遲，倒數時按 Esc；确认無新圖片且視窗還原。
5. 分別驗證 HiDPI／非 HiDPI、負座標、不同螢幕長寬比、視窗尺寸限制、目的螢幕斷線及 repeat。

## 第二階段：CLI 建立與控制項追蹤（已實作，待手動驗收）

- 使用 BetterDisplay CLI 取代直接調用未公開的 `CGVirtualDisplay`；沒有可用 4K 螢幕時詢問建立，也可從清單明確選擇建立。
- 保存唯一名稱與 tagID／serial／vendor／model 指紋；只重新連接自建螢幕。退出 FShot 時保留螢幕定義與連線，使用者可在 BetterDisplay 手動斷开或移除，不自動清理外部資源。
- `Ctrl+Shift+W` 選取視窗標題列／外框或控制項，AX 所屬視窗與 CGWindowID 必須唯一對應；移動後重新讀取元件邊界，身分失效時中止並還原視窗。
- `Ctrl+Shift+Q` 重複同一個 native target，不再次選取其他視窗。
- 程式測試涵蓋取消、AX 所屬身分驗證、布局改變、控制項消失、repeat、CLI 逾時重試與身分變更拒絕。

手動驗收：選取非作用中視窗的標題列；選取可追蹤控制項並確認原生像素輸出；延遲時關閉／改變控制項；取消後確認視窗還原；透過選單建立螢幕、重試及重開 FShot，確認只沿用自建資源，既有 `FShot-4K` 不被重新配置。

## 第三階段：延遲操作預覽（待實作）

- 使用 ScreenCaptureKit stream 與單張最新畫面信箱。
- 非啟用預覽保留目標鍵盤焦點；Quartz event tap／CGEventPost 轉送滑鼠並排除自行注入的事件。
- 首張畫面就緒後才開始倒數，處理選單列與彈出視窗的擷取範圍。
- 在取消、焦點切換、目標消失、螢幕拔除與輸入錯誤後解除 event tap、釋放按鍵並還原游標／視窗。
